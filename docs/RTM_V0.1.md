## 2. 비기능 요구사항 및 정량 목표

수치는 소규모 교내 웹 서비스의 초기 협의를 위한 제안값이다. 고객 확정값이나 모든 서비스에 적용되는 공통 표준으로 간주하지 않는다.

| NFR ID | 항목 | 목표·제약 | 측정·검증 방법 | 목표 상태 |
|---|---|---|---|---|
| NFR_01 | 등록 업무 효율 | 물품 1건 등록 완료 시간 중앙값 60초 이하 | 대표 사용자 5명에게 동일한 안내 후 각 10건의 가상 물품 등록을 수행하게 한다. 입력 시작부터 저장 완료 표시까지 총 50건을 측정한다. 현행 방식도 동등한 난이도로 측정하여 비교한다. | 정량값·시험 조건 제안. 현행 기준선과 필수 입력 항목 확인 후 확정 |
| NFR_02 | 공개 정보 제한 | 개인 휴대전화 번호 비공개 및 결정된 정보 공개 범위 준수 | 학생 조회와 문의 안내의 표시 항목을 점검한다. | 개인 번호 비공개 확정·나머지 공개 항목 미정 |
| NFR_03 | 가상 데이터 사용 | 가상 데이터만 사용하고 실제 개인정보 제외 | 예시·저장·시험 데이터를 점검한다. | 확정 |
| NFR_04 | 학교 인증 연동 제외 | 학교 인증 시스템과 연동하지 않음 | 구현·설정·실행 흐름을 점검한다. | 확정 |
| NFR_05 | 조회 성능 | 조회 응답 시간 p95 2초 이하 | 가상 물품 1,000건, 동시 사용자 20명, 사용자별 조회 완료 후 3초 대기. 예열 1분 후 10분 동안 요청 시작부터 결과 표시 완료까지 측정한다. 오류·시간 초과는 별도 보고하고 발생 시 원인 해소 후 재측정한다. 서버·브라우저·네트워크 조건을 기록한다. | 목표값·데이터 규모·부하 조건 모두 신규 제안 |

p95는 측정한 조회 응답 시간의 95백분위수이다. 일반적인 데이터 정확성은 별도 NFR에서 제외하고 해당 기능의 저장·상태 표시 검증으로 확인한다. 구체적인 고객 제약인 개인 번호 비공개와 가상 데이터 사용은 유지한다. 근거가 없는 가용성·접근성·유지보수성 등의 일반 품질 항목은 추가하지 않는다.

## 4. 이번 비기능 요구사항 정리 이력

SRS와 RTM의 현재 ID를 일치시켰다. 이전 SRS의 NFR 번호를 인용한 자료가 있다면 아래 변경표를 적용한다.

| 이전 SRS ID | 현재 ID·처리 | 변경 내용 |
|---|---|---|
| NFR_01 | NFR_01 | 등록 시간 중앙값 60초 이하와 측정 조건을 제안 |
| NFR_02 | NFR_02 | 고객의 구체적인 공개 제한 유지 |
| NFR_03 | 독립 NFR 삭제; FR_02, FR_05, FR_06에서 검증 | 일반적인 기능적 정확성을 별도 품질 요구에서 제외 |
| NFR_04 | NFR_03 | 가상 데이터 제약 번호 변경 |
| NFR_05 | NFR_04 | 학교 인증 연동 제외 번호 변경 |
| 없음 | NFR_05 신규 제안 | 조회 응답 p95 2초 이하 및 부하 조건 제안 |
