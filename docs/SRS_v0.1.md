## 1. 기능 요구사항

기능 요구사항은 시스템이 제공할 동작을 정의한다. 범위 미정 항목은 구현 의무로 확정하지 않는다.

| ID | 기능명 | 요구사항 | 검증 기준 | 상태 및 남은 확인 사항 | 근거 |
|---|---|---|---|---|---|
| FR_01 | 분실물 조회 | 학생은 방문 전에 등록된 분실물 정보를 조회할 수 있어야 한다. | 조회 대상 가상 물품을 등록한 뒤 학생 조회에서 허용된 정보를 확인할 수 있다. | 포함·세부 미정: 검색 조건, 일치 기준, 공개 항목 | NEEDS_1, SC1, S1 |
| FR_02 | 보관 여부 확인 | 학생은 조회한 물품의 보관 여부를 확인할 수 있어야 한다. | 보관 중인 물품의 보관 여부를 확인할 수 있으며, 인도 완료 물품을 보관 중으로 안내하지 않는다. | 포함·세부 미정: 인도 완료 물품의 학생 조회 노출 여부와 방식 | NEEDS_1, NEEDS_3, SC1, SC3 |
| FR_03 | 보관 위치 확인 | 학생은 보관 중인 물품의 보관 위치를 확인할 수 있어야 한다. | 조회한 보관 중 물품의 보관 위치가 결정된 공개 범위에 따라 표시된다. | 포함·세부 미정: 위치 정보의 상세 수준 | NEEDS_1, SC1 |
| FR_04 | 물품 정보 등록 | 행정 담당자는 조회에 필요한 물품 정보를 등록할 수 있어야 한다. | 결정된 입력 기준을 만족하는 가상 물품을 등록하면 저장되고 조회 대상에 반영된다. | 포함·세부 미정: 필수 입력 항목, 입력 검증 규칙, 역할별 권한 | NEEDS_2, SC2, S2 |
| FR_05 | 보관·인도 상태 기록 | 행정 담당자는 물품의 보관 중·인도 완료 상태를 기록할 수 있어야 한다. | 물품의 보관 상태를 기록하고, 실제 인도를 가정한 처리 후 인도 완료 상태가 저장됨을 확인한다. | 포함·세부 미정: 처리 권한, 상태 변경 조건, 정정 방법 | NEEDS_3, SC3, S2 |
| FR_06 | 상태 구분 | 행정 담당자는 보관 중 물품과 인도 완료 물품을 구분할 수 있어야 한다. | 두 상태의 가상 물품을 조회했을 때 각 상태를 식별할 수 있다. 별도 필터 제공 여부는 확정하지 않는다. | 포함·세부 미정: 구체적인 표시 방식 | NEEDS_3, SC3, S2 |
| FR_07 | 담당 부서·문의 방법 안내 | 학생은 물품의 보관 담당 부서와 문의 방법을 확인할 수 있어야 한다. | 담당 부서와 문의 방법이 표시되며 개인 휴대전화 번호는 공개되지 않는다. | 포함·세부 미정: 부서명, 문의 수단, 안내 내용 | NEEDS_4, SC6, SC8 |
| FR_08 | 습득물 인계 장소 안내 | 프로그램 제공 범위로 채택되는 경우, 습득 학생이 물품을 맡길 장소를 확인할 수 있어야 한다. | 포함 결정 후 안내 내용과 표시 위치에 따라 확인한다. 미결정 상태에서는 구현 필수 검증 대상에서 제외한다. | 범위 미정: 기존 안내 존재 여부, 프로그램 안내 필요성 | NEEDS_5, SC4, S3 |

## 2. 비기능 요구사항 — 정량 목표 및 공통 제약

일반적인 품질 속성만을 선언하는 항목은 독립 NFR로 두지 않는다. 기존 데이터·상태 정확성은 FR_02, FR_05, FR_06의 기능 검증 기준에서 확인한다. 아래 수치는 소규모 교내 웹 서비스의 초기 검증을 위한 제안값이며, 업계 공통 표준이나 고객 확정값이 아니다. 실제 데이터 규모·사용 환경·등록 항목을 확인한 뒤 합의하여 확정한다.

| ID | 분류 | 요구사항·목표 | 검증 기준·측정 조건 | 상태 | 근거 |
|---|---|---|---|---|---|
| NFR_01 | 등록 업무 효율 | 물품 1건 등록 완료 시간의 중앙값을 60초 이하로 한다. | 입력 시작부터 저장 완료 표시까지 측정한다. 대표 사용자 5명에게 동일한 안내 후 각 10건의 가상 물품을 등록하게 하여 총 50건의 중앙값을 산출한다. 현행 방식도 동등한 난이도로 측정해 도입 전후를 비교한다. | 부담 감소 방향 확정·60초 및 시험 조건은 제안. 필수 입력 항목과 현행 기준선 확인 후 확정 | NEEDS_7, S2, FR_04, Pol_13 |
| NFR_02 | 공개 정보 제한 | 조회 정보는 결정된 공개 범위를 따르고 개인 휴대전화 번호를 공개하지 않는다. | 학생용 조회와 문의 안내에 개인 번호가 노출되지 않는지 확인하고, 확정된 공개 항목 목록과 표시 항목을 대조한다. | 개인 번호 비공개 확정·나머지 공개 범위 미정 | NEEDS_6, S4, SC8, Pol_02, Pol_03 |
| NFR_03 | 가상 데이터 제약 | 개발 및 검증에는 가상 데이터를 사용하며 실제 개인정보를 사용하지 않는다. | 등록 예시, 저장 데이터, 시험 데이터에 실제 개인정보가 사용되지 않았는지 점검한다. | 확정 | C_1, Pol_01 |
| NFR_04 | 인증 연동 제약 | 이번 범위에는 학교 인증 시스템 연동을 포함하지 않는다. | 구현·설정·실행 흐름에 학교 인증 연동이 없는지 확인한다. 별도 인증 방식은 이 제약만으로 확정하지 않는다. | 확정 | C_1, Pol_01 |
| NFR_05 | 조회 응답 성능 | 분실물 조회 응답 시간의 95백분위수(p95)를 2초 이하로 한다. | 가상 물품 1,000건, 동시 가상 사용자 20명, 사용자당 조회 완료 후 3초 대기 조건으로 예열 1분 후 10분간 측정한다. 조회 요청 시작부터 결과 표시 완료까지 기록한다. 오류·시간 초과 건수도 별도 보고하며, 실패 요청이 있으면 원인 해소 후 재측정한다. 서버 사양·브라우저·네트워크 조건을 기록하여 재현한다. | 신규 제안·고객 원문에 직접적인 성능 요구 없음. 목표와 부하 조건 합의 필요 | FR_01~FR_03의 이용 흐름에서 도출한 제안, 고객의 정량 기준 없음 |

가용성·접근성·호환성·유지보수성 등은 별도 고객 요구나 구체적인 제약이 확인되지 않아 일반적인 품질 항목으로 추가하지 않는다.

## 3. 정책

정책은 기능과 품질 요구사항에 공통으로 적용되는 범위·공개·운영 규칙을 정의한다. 미정 정책은 구현자가 임의로 확정하지 않는다.

| ID | 정책명 | 정책 내용 | 상태 및 남은 확인 사항 | 근거·관련 요구사항 |
|---|---|---|---|---|
| Pol_01 | 가상 데이터 및 인증 연동 범위 | 가상 데이터를 사용하고 실제 개인정보와 학교 인증 연동은 이번 범위에서 제외한다. | 확정 | C_1, NFR_03, NFR_04 |
| Pol_02 | 개인 휴대전화 번호 비공개 | 개인 휴대전화 번호는 공개하지 않는다. 담당 부서의 문의 방법 안내와 개인 번호 공개를 구분한다. | 확정 | NEEDS_6, S4, SC8, NFR_02 |
| Pol_03 | 조회 정보 공개 범위 | 조회 목적에 필요한 공개 정보 범위를 정한다. 물품 정보와 위치의 상세 수준은 정보보호 담당자의 검토 대상이다. | 세부 미정: 공개·비공개 항목, 최종 결정 주체 | NEEDS_1, NEEDS_6, SC1, FR_01~FR_03, NFR_02 |
| Pol_04 | 물품 등록 기준 | 물품 등록에 필요한 입력 항목과 필수 여부, 입력 검증 규칙을 정한다. | 미정: 구체적인 항목과 규칙 | NEEDS_2, SC2, FR_04 |
| Pol_05 | 상태 관리 기준 | 보관 중과 인도 완료를 구분하며 실제 인도 사실을 상태 관리에 반영한다. | 구분 원칙 확정·세부 미정: 변경 조건, 잘못 처리한 상태의 정정 방법 | NEEDS_3, SC3, FR_05, FR_06 |
| Pol_06 | 역할별 처리 권한 | 물품 등록·상태 처리·정정에 대한 역할별 권한을 정한다. 행정 담당자가 등록·상태 관리를 수행한다는 역할은 확인되었으나 세부 권한은 미정이다. | 세부 미정: 권한 부여·확인 방식, 정정 가능 주체. 학교 인증 연동 제외 제약을 따른다. | NEEDS_2, NEEDS_3, SC2, SC3, C_1 |
| Pol_07 | 인도 완료 물품 조회 | 인도 완료 물품을 학생 조회에 계속 표시할지와 표시 방식을 정한다. 결정된 방식에서도 보관 중으로 오인하게 안내하지 않는다. | 세부 미정: 공개 여부, 노출 방식 | NEEDS_1, NEEDS_3, NEEDS_6, FR_02 |
| Pol_08 | 문의 안내 | 담당 부서와 문의 방법 안내를 제공한다. 개인 휴대전화 번호 공개는 포함하지 않는다. | 제공 확정·세부 미정: 담당 부서, 연락 수단, 표시 문구 | NEEDS_4, SC6, SC8, FR_07 |
| Pol_09 | 습득물 인계 장소 안내 범위 | 기존 안내 존재 여부와 프로그램 안내 필요성을 확인한 후 포함 여부를 결정한다. | 범위 미정 | NEEDS_5, SC4, FR_08 |
| Pol_10 | 사진 기반 조회 제외 | 사진을 올려 유사 분실물을 조회하거나 자동 매칭하는 기능은 이번 범위에서 제외하며 후속 개선 후보로 남긴다. | 확정 | S5, SC5 |
| Pol_11 | 매칭 결과 자동 알림 제외 | 사진 매칭 결과를 분실 학생에게 자동으로 알리는 기능은 이번 범위에서 제외한다. 이번에는 문의 방법 안내까지 제공한다. | 확정 | S5, SC7 |
| Pol_12 | 운영 책임 | 학교의 서비스 운영 책임자가 운영 정책과 책임을 결정한다. | 역할 확정·실제 담당 조직 또는 담당자 미정 | 원문 2장 |
| Pol_13 | 등록 부담 개선 평가 | 등록 부담의 원인과 현재 수준을 확인하고 측정 방법과 개선 목표를 정한다. 확정 전에는 특정 시간이나 개선율을 합격 기준으로 사용하지 않는다. | 세부 미정: 평가 지표, 기준선, 목표, 평가 조건 | NEEDS_7, 원문 1장, NFR_01 |
